## A. User journey

1. On first entry into resume creation, begin with Personal Information and preserve the existing multi-step Career Profile flow.
2. Save progress reliably. If the user leaves before completing Review, Home must offer a clear Continue action that resumes the last incomplete step.
3. Reaching Review does not mean every field is valid. Enable Preview & Export only when the defined minimum profile content is satisfied.
4. Pressing Preview & Export from Review marks the profile setup complete and opens Resume Export.
5. Pressing the corresponding action from Home for an already-completed profile opens Career, not Review.
6. Resume Export lets the user choose resume content language independently of app language and shows only compatible available templates.
7. Each template has a representative illustrative preview image and an enlarged preview action. Use clearly fictional placeholder content; do not imply the sample is the user's generated resume.
8. Show optional formatting settings only when they are genuinely supported by the existing PDF renderer. Keep unsupported controls out of the UI.
9. Preview displays the actual resume content with pagination for multipage documents. Typography, accent color, spacing, and other controls must affect the actual PDF output if exposed.
10. Export requires an explicit confirmation showing the applicable Credit charge.
11. Show a processing/waiting screen with status and resume configuration details. Update it while the screen is open. When the export completes, expose Download. If the user leaves, preserve the operation and its status in Export History.
12. Export History and Resume Details must support the states Completed/Download Available, Queued or Processing, Expired, and Failed. Display the appropriate actions and Credit impact for each state.
13. Download an existing valid PDF without additional Credits. Expired PDFs must not silently regenerate. An explicit re-export is a new billable operation under the existing policy.
14. Restrict all records, details, downloads, and actions to the authorized user.

## B. Credits, idempotency, and abuse prevention

- Preserve the current Credit pricing and reward policy. Do not change signup rewards to 10 Credits or change AI/Cover Letter pricing.
- Do not implement AI improvement or Cover Letter generation in this task.
- Enforce Credit balance and reservation checks server-side; UI disabling is only a usability aid.
- Prevent duplicate charges and duplicate operations on rapid taps, retries, timeouts, and unreliable networks using the existing idempotency and reservation model.
- Preserve the existing per-user limits: one export per rolling 5 minutes, 3 per hour, 5 per 24 hours, and 10 per 7 days, plus the existing one-active-intent rule. Inspect the current implementation and enforce the existing agreed policy; do not silently change its semantics.
- Failed exports must release reservations and must not incur a final Credit charge. Retrying must follow the existing operation lifecycle rules; never reopen a terminal FAILED operation in place.
- Keep valid existing downloads free. Re-export is a new operation and incurs the current configured Credit price.
- Keep PDF retention at 7 days. Never regenerate automatically after expiry or missing-file detection.
- Prevent excessive concurrent work. Reuse the existing queue, admission controls, Cloud Run Gateway/Worker, private storage, and budget protections rather than introducing a second processing architecture.
- Respect server-side cost admission and stop accepting new billable work when the configured budget policy denies admission. Do not rely on the mobile client or Supabase UI flags alone as the security boundary.
