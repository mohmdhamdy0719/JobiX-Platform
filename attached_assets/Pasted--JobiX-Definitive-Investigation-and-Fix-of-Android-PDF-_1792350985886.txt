# JobiX — Definitive Investigation and Fix of Android PDF Download/Save Failure

## Objective

Continue from the CURRENT repository state. Do not restart the investigation from scratch and do not repeat fixes already implemented without checking their current status.

The Android Development APK has repeatedly failed to download/save an existing completed PDF. The user previously received:

`PDF download failed`
`Android could not confirm a complete PDF save. check device storage and retry. Your existing export and Credits are unchanged`

A previous investigation found that this message can represent multiple conditions, including:

- A genuine Android write/close failure.
- A missing or malformed Flutter method-channel result.
- A reported file-size mismatch.
- An unavailable final file size reported by the Android document provider.

A plausible source defect involving SQL `NULL` from `OpenableColumns.SIZE` was corrected by checking `Cursor.isNull()` before reading the size. However, the user's actual failure was not proven to be caused by that defect, and the latest diagnostic APK still failed on the user's device.

The immediate goal is to determine the exact failure branch, obtain sufficient evidence to establish the root cause, and implement the smallest reliable fix.

## Phase 3 — Correctness requirements

The implementation must preserve PDF integrity and must not weaken validation to make the error disappear.

- A real write failure must remain a failure.
- A stream that fails to close successfully must not be reported as successful.
- A genuinely known final size that differs from the written size must be handled safely.
- An unavailable final size must be represented as unavailable, not silently converted into an actual size of zero.
- If final size is unavailable, success may be accepted only when the destination was selected, the stream opened, all expected bytes were written, the stream closed successfully, and the available PDF integrity checks passed.
- A missing or malformed method-channel result must not produce a false success.
- A successfully saved PDF must not be reported as failed merely because a legitimate document provider does not expose a final size.
- Cancellation must remain distinct from a write failure.
- A failed download must never initiate a new export.
- Downloading an existing completed PDF must never charge Credits.
- Existing ownership checks, authorization, idempotency, and server-side Credit accounting must remain unchanged.

Only implement the smallest fix justified by the evidence. Do not rewrite unrelated export or backend architecture.
