Jobix: Core Validation and Storage Matrix

Prepared for owner review • October 3, 2026 • Existing native Foundation and Architecture V2 remain in place.

PROPOSAL — NOT APPROVED OR IMPLEMENTED.
Only the separately approved zero-credit development-account provisioning has been performed. Approval of this document would authorize the proposed rules below, not a new architecture, provider substitution, translation feature, or production deployment.

1. Already approved — unchanged

  • Work Experience, Summary, and Target Role are optional. Skills alone do not satisfy Minimum Meaningful Career Content (MMCC).
  • Summary: 50–1,000 characters when used. Work Experience description: 20–1,500 characters when used.
  • Completeness weights: Contact 15, Career Evidence 45, Skills 15, Summary 10, Languages 10, Target Role 5. First meaningful evidence item contributes 30; second contributes 15; later items add no extra weight.
  • The first-profile AI phase ends permanently at 50% completeness; unused first-profile generations do not carry over. The next-Cairo-day Free allowance remains unchanged.
  • Export needs valid full name, email, phone, MMCC, and complete included sections. Low completeness or ATS readiness alone does not block export.
  • Career Profile holds professional data. Resume language/template/visibility are presentation configuration, not extra Profiles or automatic content translation.
  • Exactly three slots: first free, second 10 Credits, third 20 Credits. Purchased slot entitlements survive Profile deletion.

2. Proposed common rules

  • Partial progress: structurally valid incomplete items can be saved and synchronized. Missing completion fields are not a reason to discard progress. They become In Progress or Needs Attention, not Complete.
  • Hard constraints: over-limit text, malformed dates/URLs, inconsistent date ranges, and invalid field types are rejected by the server. The local encrypted draft is retained for correction. Never truncate or silently rewrite existing content.
  • Text: limits count Unicode code points after trimming outer whitespace, matching PostgreSQL character length and a corresponding Flutter counter. Store original internal spacing and wording. Validate plaintext and escape it in rendering.
  • Completion: evaluate the accepted current server content only, not rejected/unaccepted AI proposals, hints, sample placeholders, or unrelated onboarding answers.
  • Meaningful-content filter: required text must contain letters or digits rather than only punctuation. Required descriptions must not consist of a single character repeated to meet their minimum length. Exact placeholder values such as “test”, “asdf”, “todo”, “tbd”, “n/a”, “example”, “placeholder”, “اختبار”, “مثال”, and “غير متوفر”, and standard lorem-ipsum filler, do not qualify. Keep such drafts but mark them Needs Attention. This is a deterministic minimum-content check, not proof of truth or an AI quality score.
  • Visibility: a section not yet added is absent. Adding it enables it; incomplete enabled sections block export until completed, removed, or explicitly disabled. Resume visibility does not manufacture or erase profile facts and does not change data completeness.
  • Minimum short text: newly defined labels require at least 1 trimmed code point when used, preserving legitimate short names and skills such as C and R. Target Role requires 2. Existing valid Personal Information format validation is preserved.

4. Proposed dates, URLs and duplicates

  • Dates: collect month/year for career sections, store a PostgreSQL date with day 01 as a normalization convention, and render month/year only. That stored day must never be presented as an asserted event day. No invented earliest-year rule or blanket future-date ban.
  • Ranges: end month cannot precede start month. Present means is_current=true and no end date. Missing required date components leave an item incomplete. Impossible dates are rejected.
  • URLs: accept valid HTTPS URLs; a bare web domain/path may be normalized to HTTPS. Reject unsafe schemes and embedded credentials. A nonblank malformed optional URL must be corrected or cleared. No invented allowlist of employer/institution domains.
  • Skills/languages: prevent same-profile duplicate names using trimmed, case-insensitive comparison with collapsed whitespace in the comparison key only. Preserve display wording; do not merge different real skills or languages.
  • Evidence duplicates: users may retain repeated content, but exact normalized duplicate evidence payloads count only once toward the 30/15 evidence contribution. Two distinct items may be in the same section; do not require employment or two different evidence categories.

MMCC guard proposal: cap the displayed/stored total at 49% while no meaningful evidence item exists. The document fixes the 50% transition but not this exact cap. This prevents the other categories (which can total 55) from ending the first-profile AI phase without MMCC.

An incomplete extra item does not erase valid evidence/category points. It still blocks export if its section is enabled. Incomplete content remains editable. Store the score server-side with a versioned deterministic algorithm; latch the first-profile transition atomically with the successful mutation that reaches 50%.
