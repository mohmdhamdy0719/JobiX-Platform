# JobiX DESIGN.md

**Version:** 1.0  
**Status:** Official First Release — Ready for Stitch  
**Product:** JobiX  
**Platform:** Mobile-first application, implemented in Flutter  
**Primary UI languages:** English + Arabic  
**Direction:** LTR + RTL  
**Design objective:** Premium, trustworthy, modern career-product UI with low cognitive load and strong professional credibility.

---

# 1. Design North Star

JobiX should feel like a **serious career tool**, not a generic AI chat app and not a flashy resume-template marketplace.

The visual language should communicate:

- Professionalism
- Confidence
- Clarity
- Trust
- Progress
- Intelligent assistance
- Control by the user

The interface should make a user feel:

> “I know what to do next, my information is safe, and JobiX is helping me present myself better.”

The design must prioritize usability over visual novelty.

### Core design principles

1. **Clarity over decoration**
2. **Professional over playful**
3. **Confident over aggressive**
4. **Helpful over overwhelming**
5. **Human-controlled AI**
6. **Progress without pressure**
7. **Consistent components over one-off screens**
8. **Mobile-first touch ergonomics**
9. **Arabic and RTL are first-class**
10. **Accessibility and readable contrast are non-negotiable**

# 2. Brand Identity

## Logo

Use the provided JobiX logo assets as the primary brand reference.

The brand mark combines a stylized **J + X/check-like motion** and represents forward career movement and achievement.

Provided reference assets include:

- Horizontal JobiX logo on Midnight Navy
- Vertical/splash composition
- App icon with navy background
- App icon with white background
- Large brand mark

### Logo rules

- Never redraw or modify the logo.
- Preserve the original proportions.
- Do not add unnecessary effects around the logo.
- Use the full logo when there is sufficient horizontal space.
- Use the standalone mark for app icons, compact headers, avatars/brand marks, and constrained spaces.
- Maintain generous clear space around the logo.
- Do not place the full logo inside dense UI cards.

### Brand imagery

The provided logo imagery establishes the brand direction:

- Deep navy
- White
- Electric/royal blue
- Subtle forward-motion feeling
- Premium but minimal

The large decorative J/X artwork may be used sparingly in onboarding, splash, empty states, or brand moments. It must not become a repeated background pattern behind dense product content.

The existing palette should **not** be replaced.

- Most product screens should remain light and calm.
- Do not make the whole application dark simply because the logo has a dark background.
- Use navy as a strong anchor, not as the background of every screen.

### Important

Do not introduce additional arbitrary colors.

If a new color appears necessary, derive it from the existing palette or document why it is required.

# 5. Layout System

JobiX is mobile-first.

### Base spacing scale

Use a consistent 4pt/8pt-oriented spacing system.

Recommended values:

- 4 — micro spacing
- 8 — icon/text and compact spacing
- 12 — small component spacing
- 16 — default component padding
- 20 — section spacing
- 24 — major section spacing
- 32 — screen-level separation
- 40 — large hero spacing
- 48+ — major brand moments

Do not create random spacing values unless necessary.

### Screen margins

Default mobile horizontal content margin:

**16–20px**

Use wider margins for onboarding/brand screens when visually appropriate.

### Touch targets

Interactive controls should generally provide at least a comfortable mobile touch target around **44–48px**.

---

# 6. Corner Radius

Use a restrained radius system.

Recommended:

- Small controls/chips: 8px
- Inputs/buttons: 10–12px
- Cards: 14–16px
- Large sheets/hero containers: 20–24px

Avoid making every component extremely rounded.

The product should feel professional rather than toy-like.

---

# 7. Shadows and Elevation

Use shadows very sparingly.

Preferred visual hierarchy:

1. Flat background
2. Border
3. Very subtle elevation
4. Strong elevation only for modal/sheet layers

Cards should generally use:

- White background
- `#E2E8F0` border
- Very subtle shadow when needed

Avoid heavy floating-card shadows.

---

# 8. Typography

Typography should be highly readable and professional.

## Recommended font strategy

Use a modern neutral sans-serif with excellent Latin + Arabic coverage.

The implementation should use a font family that supports:

- English
- Arabic
- numbers
- mixed Arabic/English text
- proper RTL shaping

Preferred direction:

- **Inter** or equivalent for Latin
- **Noto Sans Arabic** or equivalent for Arabic

If a single family with strong bilingual support is selected, use it consistently.

### Hierarchy

Recommended starting scale:

- Display: 30–36px, bold
- H1: 28–32px, bold
- H2: 22–24px, semibold/bold
- H3: 18–20px, semibold
- Body: 15–17px, regular
- Secondary: 13–15px
- Caption: 12–13px

Typography should be tuned by screen, not blindly applied.

### Headings

Headings should be confident and concise.

Avoid:

- all-caps UI headings
- overly thin typography
- excessively large headings on dense product screens

- Text: white

- Height: approximately 48px
- Semibold label
- Strong but not oversized

Examples:

- Continue

- Improve with JobiX
- Use This
- Add Experience

## Secondary button

- White/transparent background
- Border: `#CBD5E1`
- Text: `#111827`

## Tertiary / text action

- No container

# 10. Inputs

TextFields should feel calm and easy to scan.

Default:

- Background: white
- Border: `#CBD5E1`
- Focus border: `#2563EB`
- Radius: 10–12px
- Clear label
- Helpful supporting text when needed

Error:

- Border: `#EF4444`
- Clear inline explanation
- Do not rely only on color

### AI writing fields

Writing fields should visually communicate that the user owns the content.

Recommended structure:

```text
Label
[ Description / content field ]

Not sure what to write?
› Hint
› Hint
› Hint
```

Hints are guidance, not additional input fields.

Do not make the interface look like a chatbot.

---

# 11. Cards

Cards are a core JobiX pattern.

Default:

- White
- Border `#E2E8F0`
- Radius 14–16px
- Minimal shadow

Use cards for:

- Career Profile summaries
- ATS Readiness
- Profile sections
- AI proposals
- Export history
- Credit balance
- Daily Reward
- Recommendations

Do not put every small piece of information in its own card.

# 12. AI Visual Language

AI is important to JobiX but must never visually dominate the product.

The UI should communicate:

> “JobiX is helping you improve your content.”

Not:

> “An AI is taking over your CV.”

## AI actions

Preferred wording:

- Improve with JobiX
- Generate suggestion
- Review suggestion
- Use This
- Keep Mine
- Regenerate

Avoid:

- Magic Rewrite
- AI Will Fix Everything
- Auto Optimize without review
- misleading claims

## AI proposal component

Use a clear comparison/proposal layout:

```text
Your version
[Original text]

JobiX suggestion
[Proposed text]

[Keep Mine]   [Use This]
```

The original must remain visible/recoverable.

### AI generation counter

Show remaining allowance clearly but quietly.

Example:

> 3 of 6 generations used

or

> 3 generations remaining today

Do not make the user feel punished for using AI.

---

# 13. ATS Readiness UI

ATS Readiness should look useful and analytical, not like a fake hiring prediction.

Use:

- score
- status
- key issues
- actionable recommendations

Example:

```text
ATS Readiness
67 / 100

Good foundation

3 areas could be improved

• Add clearer achievement details
• Improve experience descriptions
• Add relevant skills
```

The score should never visually imply:

- hiring probability
- job-match percentage
- guaranteed ATS acceptance

### Profile Completeness

Keep it visually distinct from ATS Readiness.

Example:

```text
Profile Completeness
82%

ATS Readiness
67 / 100
```

These are different concepts and must not be merged into one score.

---

# 14. Progress Indicators

Progress should encourage completion without creating pressure.

Use:

- progress rings
- progress bars
- section completion indicators
- checkmarks
- subtle status badges

Suggested states:

- Complete
- Needs attention
- Optional
- Not started

Avoid aggressive red states for normal incompleteness.

# 17. Home — Career Command Center

Home is not a marketing page.

It should answer:

1. What is my current Career Profile?
2. How complete is it?
3. How ATS-ready is it?
4. What should I do next?
5. How many Credits do I have?
6. Can I claim today's Daily Reward?
7. What did I export recently?

Suggested hierarchy:

```text
Greeting / profile context

Current Career Profile
[Profile name]
[Completeness] [ATS Readiness]

Next best actions
[Continue Profile]
[Improve CV]

Credits
[Balance] [Daily Reward]

Recent exports

```

Keep Home actionable and calm.

# 20. Onboarding

Onboarding consists of three concise brand/product screens followed by four quick research questions.

## Screen 1

**Title:**
Build a professional, ATS-friendly CV

**Description:**
Create a CV that clearly presents your experience, skills, and strengths — without the hassle of starting from scratch.

## Screen 2

**Title:**
Turn your experience into professional content

**Description:**
Describe your experience in your own words. JobiX can help refine it into clear, professional CV-ready content — without inventing information.

## Screen 3

**Title:**
Create it once. Update it anytime.

**Description:**
Choose your CV template, export it as a PDF, and keep your information ready to update whenever your career changes.

### Onboarding visual direction

Use the JobiX brand:

- deep navy
- blue accent
- white
- subtle gradients
- logo/mark
- generous whitespace

Do not overload onboarding with feature lists.

The experience should feel premium and fast.

# 22. Credits and Daily Reward

Credits are important but should not make JobiX feel like a game.

### Credits

Use a compact balance component.

Example:

```text
Credits
12
```

Use blue/navy branding rather than gold coins or gaming imagery.

### Daily Reward

The Daily Reward can use a small reward card:

```text
Daily Reward

Watch a short rewarded ad
Get +2 Credits

[Claim Reward]
```

If unavailable:

```text
Daily Reward
Already claimed today
```

Do not use gambling-like visual language.

# 23. Resume Preview

Preview is one of the most important product moments.

It should feel like a professional document viewer.

The UI should clearly separate:

- document preview
- document actions

Primary action:

**Export PDF**

Secondary actions:

- Edit
- Change template
- Change CV language where supported

The Resume itself must remain visually clean and conventional.

# 24. Resume Template UI

The Resume template is not the same thing as the app UI.

The exported Resume should prioritize:

- ATS readability
- single-column reading order where appropriate
- conventional section headings
- selectable text
- information hierarchy
- clean page breaks
- Arabic RTL when applicable
- English LTR when applicable

Do not carry app-style cards, gradients, large buttons, or decorative UI into the PDF.

---

# 25. Export History

History is a practical utility screen.

Each item can show:

- Profile name at export time
- Date/time
- Template
- CV language
- Page count
- File availability

Actions:

- Download/share existing valid PDF
- Export Again after expiry

Expired files should look clearly expired without making the historical record disappear.

# 26. Settings

# 27. Empty States

Empty states should always explain:

1. What is empty?
2. Why it matters?
3. What can the user do next?

Example:

```text
No experience added yet

Add your work experience to make your Career Profile stronger.

[Add Experience]
```

Avoid generic:

> Nothing here.

---

# 28. Error States

Errors must be:

- specific
- understandable
- actionable
- non-technical

Bad:

> Error 500 / synchronization failed.

Better:

> We couldn't save your latest changes. Your local progress is still safe.

[Try Again]

Never imply that user data is lost unless it actually is.

---

# 29. Loading States

Use skeletons or calm progress indicators.

Avoid unnecessary full-screen spinners.

For AI:

```text
JobiX is reviewing your content…

This may take a moment.
```

Do not make AI generation look like a chatbot conversation.

---

# 30. Offline / Sync UI

Offline state should be subtle.

Examples:

- “Saved on this device”
- “Syncing…”
- “Saved”
- “Changes waiting to sync”

Do not block the user from editing merely because sync is unavailable.

If a sync conflict occurs, explain it clearly and preserve the user's work where possible.

---

# 31. Arabic and RTL Design Requirements

Arabic is not a translated-afterthought.

Every major screen must be designed for both:

- English LTR
- Arabic RTL

RTL must affect:

- text alignment
- navigation direction
- icon placement where directional
- back/forward controls
- lists
- cards
- progress layouts
- form layouts
- date/number presentation where appropriate

### Important

Do not mirror icons that are semantically universal.

Directional icons should mirror where appropriate.

Mixed Arabic/English content must remain readable.

---

# 32. Accessibility

The UI must maintain accessible contrast.

Do not rely on color alone to communicate:

- errors
- success
- incomplete states
- selection
- disabled states

Use:

- text
- icons
- labels
- borders
- state changes

Interactive elements need comfortable touch targets.

Text should remain readable when system font size is increased.

---

# 33. Motion

Motion should communicate state, not decorate the interface.

Good uses:

- screen transitions
- progress changes
- expanding hints
- AI generation state
- success confirmation
- modal/sheet presentation

Avoid:

- constant floating animations
- excessive parallax
- distracting background movement
- long animations that slow down productivity

Recommended motion feel:

**fast, smooth, confident.**

---

# 34. Responsive Behavior

Although JobiX is mobile-first, layouts should adapt gracefully to larger screens.

### Mobile

- single-column
- bottom navigation
- full-width primary actions
- compact cards

### Tablet / larger

- wider content max-width
- more breathing room
- optional two-column layouts where useful
- maintain the same hierarchy and component system

Do not simply stretch mobile cards across the entire screen.

- Hover where relevant
- Pressed

# 37. Visual Hierarchy Rules

On every screen, users should immediately understand:

1. Where am I?
2. What is the primary task?
3. What information matters most?
4. What can I do next?

Use hierarchy through:

- typography
- spacing
- grouping
- contrast
- restrained color
- component placement

Do not solve hierarchy by making everything bold or blue.

---

# 38. Brand Usage in Product UI

The JobiX logo and blue accent should create recognition, not decoration.

Recommended frequency:

- Logo: onboarding, authentication, key brand moments
- Navy: major navigation/headers
- Royal Blue: actions and active states
- Deep Blue: secondary emphasis
- White/slate surfaces: majority of everyday workspace

The everyday Career Builder should feel predominantly **light, clean, and focused**.

---

# 39. What Stitch Must NOT Do

Do not:

- redesign the JobiX logo
- replace the approved color palette without justification
- turn JobiX into a dark-only application
- create a generic AI chatbot interface
- make AI the center of every screen
- use excessive gradients
- use excessive glassmorphism
- use gaming-style Credits
- use hiring-probability visuals
- merge ATS Readiness and Profile Completeness
- invent new navigation destinations
- invent new product features
- invent new business rules
- create fake metrics
- use decorative UI that harms readability
- design only English and assume RTL will work automatically
- create UI that cannot be implemented cleanly in Flutter

# 41. Implementation Alignment

The final UI will be implemented in Flutter.

Therefore:

- Use conventional mobile interaction patterns.
- Avoid designs dependent on unsupported web-only behavior.
- Keep components reusable.
- Keep layouts deterministic.
- Make states explicit.
- Design for real content lengths, not placeholder text only.
- Test long names, long experience descriptions, multiple skills, Arabic content, and multi-page resumes.
- Do not design a UI that requires a separate web application to reproduce.

# 43. Final Design Statement

JobiX should look like a product users can trust with an important part of their professional life.

The final experience should be:

**Clean. Professional. Intelligent. Calm. Confident. Human-controlled.**

The design should make the user's career information the hero — not the interface, not the AI, and not the brand decoration.
