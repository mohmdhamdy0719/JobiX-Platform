Resume creation starts at Personal and preserves the six-step builder. Persist
unfinished setup progress per account/profile. Visiting Review is not completion
or proof of validity: the explicit Preview & Export action, with the existing
structural minimum satisfied, completes setup. Thereafter Home opens Career.
Do not equate this marker with profile completeness or alter the existing 50%
AI transition.

**Why:** The owner explicitly requested this journey while preserving the existing
MVP, structural minimum, optional sections, and completeness policy.

**How to apply:** Keep setup completion independent of percentage calculations.
Current setup progress is an encrypted local preference, not a server-synced
completion claim. A server completion contract would require separately approved
schema work. Keep owner-scoped resume preferences inside the existing account
cleanup namespace.

Frozen request configuration may supplement native presentation in encrypted,
account/job/profile-scoped local metadata. It must never override server job
state, Credits, cost, counts, or download eligibility, and must never become a
synthetic history record.

**Why:** The existing status/history contract does not expose all frozen
configuration details. Guessing from an edited current profile would misrepresent
an older PDF.

**How to apply:** Preserve frozen metadata across same-key recovery, omit absent
historical/cross-device fields, and require an approved backend read-contract
extension before promising complete cross-device configuration history.

The supplied screenshots govern hierarchy and visual style, but not invented
backend capabilities. Template specimens must be clearly fictional. Expose only
real renderer-supported options and actual saved content. Never fabricate ATS
scores, additional templates, progress percentages, provider timing, or Credit
balances.

**Why:** The owner requires a functional native journey, not a screenshot-only
prototype or unsupported formatting controls.

**How to apply:** Preserve the backend’s canonical document/version checks and
Credit/idempotency/lifecycle authority. No new AI, Cover Letter, buying Credits,
reward-policy changes, or invasive device fingerprinting in this increment.

Stop at the live-activation checkpoint. Enabling export requires separately
approved cost assumptions, accounting readiness, verified Gateway/Worker gate
configuration, and a disable/rollback plan. Local disposable fixtures are not
live activation evidence; an estimated admission budget is not an invoice cap.

**Why:** The owner explicitly prohibits automatic activation, paid tests, or
cloud changes while building the native experience.
The owner also confirmed installation and launch on physical Android but
rejected Preview usability while export was disabled; build/install success
does not establish document readability or live export success.

**How to apply:** Report outstanding eligibility, runtime, signing, and physical
device verification limitations without enabling gates or inventing approval.

## Local Preview integration boundary

The owner approved integrating the isolated Local Preview into the production
Resume journey after the narrow source inspection. Use fresh saved profile,
custom-link, and presentation data; show an explicit saved-version confirmation
when local drafts exist; never save or discard edits merely by opening Preview.

**Why:** The owner approved this behavior to preserve complete local review without
changing the existing server-authoritative export contract.

**How to apply:** Reuse the shared renderer and bundled assets. Keep generated
Preview HTML in memory, clean up route/WebView resources, prevent unbounded
memory/storage growth, and do not persist Preview output in resumes or history.
Block unresolved save requests and unsupported saved settings rather than
silently omitting data. Before PDF submission, re-fetch the authoritative
document and require the existing review flow if it differs. Do not build or
deploy a production APK until the owner reviews the implementation report.
