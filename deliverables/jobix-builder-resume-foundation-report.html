Jobix: Builder polish & Resume foundation

Development milestone. Not a production release or real-device acceptance.

A. Fixed

  • Step 1 and Review have no on-screen Back action; Review uses Done. Review-origin editors save back to Review without the normal builder footer. Removed the redundant Career Review button.
  • Clearer input surfaces, selected CV-language indication, editable account-email suggestion, and email validation on blur/submit.
  • Offline English/Arabic country autocomplete follows CV language. Six exact Summary guidance questions with illustrative-only examples.
  • Mobile YYYY-MM masking, Arabic digits, date validity/order, structural-field blocking and nonblocking short-description attention.
  • Bundled IBM Plex Sans Arabic with Inter for Latin text.
  • First-launch completion is separate from account-owned answers. Sign-out keeps completion and clears private account drafts. Research attachment requires registration binding, not merely a signed-in account.

B. Implemented

  • Optional device photo selection/replacement/removal and custom labelled HTTPS links. JPEG/PNG images are bounded to 1 MiB and stored in an owner-protected development database record, not a public bucket. This avoids repurposing the PDF-only GCS bucket.
  • Encrypted local drafts, exact pending-request replay and explicit conflict handling for extras.
  • Server-returned AI allowance display, first-profile allowance foundation and 50% transition latch. The proposal component supports original/proposal presentation and explicit acceptance callbacks; no generation is enabled.
  • Worker-only Credits reservation, release and consume functions with locking, operation identity, fencing and expiration checks. Existing +5 signup behavior is preserved. Failed/released reservations do not permanently debit the wallet.
  • Owner-scoped Resume configuration referencing the existing Career Profile, English/Arabic ATS template identifiers, canonical escaped HTML with embedded fonts, selectable text, RTL/LTR, A4 print styles and no single-page clipping.
  • Native WebView preview screen and Career entry point. Preview does not charge Credits. Configuration retries preserve the original request; conflicts offer explicit saved-configuration reload.

C. Verified

  • Flutter static analysis and the existing automated suite, including new extras, allowance and renderer coverage. Native English/Arabic widget captures were inspected. See the accompanying chat for final run counts.
  • Actual isolated-development PostgreSQL transactional tests: structural validation, private extras access, stale versions, Resume configuration without duplicate profiles, server allowance response, Credits reserve/release/consume and duplicate-finalization protection.
  • Additive migrations applied only to the approved development database. Test-account fixtures were rolled back. No production migration, Vertex-generation or live-device success is claimed.

D. Not yet implemented

  • Live gemini-3.5-flash global-endpoint request flow; AI operation reservation/reconciliation, generation history, version-checked proposal acceptance and factual clarification. Generation stays disabled rather than returning fabricated results.
  • Premium entitlement wiring. Existing accounts remain Free; no subscriptions or billing were introduced.
  • Chromium PDF worker, exact paginated PDF verification, private PDF storage/download lifecycle and export-to-reservation integration. The current WebView is a continuous A4-width document; print CSS is the foundation, not proof of final PDF pagination.
  • Profile 2/3 paid unlock flows, Cover Letter, Professional Email, rewards and advanced paid features.
  • Photo inclusion in Resume templates. The private profile photo is managed separately; current ATS templates are text-first.

E. Requires real Android device

Gallery permissions and picker recovery, photo sync after relaunch, keyboard/date behavior, WebView font rendering/zoom/selection, Android back behavior, secure-storage/process-death recovery and full email-confirmation callback regression. Host tests and APK compilation do not prove these.

F. Next recommended task

Complete the server AI request/state/history/acceptance path against the approved global model, including quota reconciliation and failure release, before enabling Improve with Jobix. Separately validate the current Android photo and Resume-preview flows on the owner's device.
