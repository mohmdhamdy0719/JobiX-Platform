**Screen:** Settings → Account Information.

- A field for the new email address.
- `Cancel` and `Send confirmation` actions.

Validate the email and prevent submission if it matches the current email or is invalid. Disable duplicate submissions while a request is in progress.

## 11. PDF Export — Critical Root-Cause Fix

**This is the highest-priority functional issue.**

The current app still displays:

**Title:** `PDF request issue`

**Message:** `The saved document changed. Review the current Preview before creating a new export.`

The same error also appears below `Preview & Export` on the Resume Export screen.

This error must not be treated as a cosmetic issue. Determine why the document is considered changed, fix the actual defect, and prove the corrected behavior with a regression test.

### Investigation requirements

Trace the full flow through the existing implementation:

1. How the profile is loaded and saved.
2. How the authoritative Supabase-saved document is identified.
3. When the save operation is confirmed to the client.
4. How the preview snapshot, revision, version, canonical representation, or hash is produced.
5. What the export request sends to the backend.
6. How the backend compares the current saved document with the preview/export request.
7. Whether a refresh, asynchronous update, normalization, serialization, or stale client state causes a false mismatch.
8. Whether local recovery data is incorrectly being treated as saved data.
9. How export reservation/idempotency and document versioning interact.

Identify the specific root cause in code and/or a reproducible test. Do not guess, simply retry, or weaken the server's integrity checks.

### Required behavior

After a user saves a profile:

- Wait for the authoritative save to complete.
- Ensure the preview is built from the confirmed saved document/revision.
- Ensure the export request refers to the same saved version the user reviewed.
- A normal save → preview → export flow must succeed without a false mismatch.
- If the saved document genuinely changes after preview, reject the stale request safely and provide a clear way to refresh/review the current document.
- Once the user reviews the current version, do not repeatedly show the same stale-state error unless the document actually changed again.
- Do not silently overwrite newer server data with an old local copy.
- Do not lose unsaved user edits.
- Do not create duplicate export jobs or reservations during retries.

### Credit safety

- A new successful PDF export costs 2 Credits.
- A valid existing PDF download is free while the PDF remains available.
- A failed export must not incur a final charge.
- Preserve server-authoritative Credit accounting, reservations, finalization, release, and idempotency.
- Do not perform live exports or debit Credits during automated tests.

### Regression tests

Add a focused test reproducing the original false mismatch, then prove the corrected save → preview → export flow. Also test a genuinely stale preview and verify that integrity protection still works.

The final report must state the actual root cause, affected code path, fix, regression test, and any remaining backend/configuration limitation.

Do not claim the export issue is fixed merely because the UI error disappeared or the APK builds.
