### 2. Resume Details — Repeated Refresh and Unusable Download Controls

**Observed problem:** The bottom `Refresh details` control repeatedly displays a loading indicator approximately every 2–3 seconds. This makes the page feel unstable and interferes with tapping the download action.

Requirements:

1. Trace every source of detail refreshes, including timers, polling, lifecycle callbacks, widget rebuilds, listeners, automatic retries, and asynchronous state updates.
2. Determine exactly what causes the repeated refresh and fix the underlying trigger. Do not merely hide the loading indicator.
3. Remove unnecessary periodic refreshes. Resume details must not refresh repeatedly when the record has not changed and no legitimate operation is pending.
4. Load details when the page opens, and refresh after a relevant operation or explicit user action when necessary.
5. Prevent overlapping requests and duplicate fetches. Ensure loading state is reset on success, failure, timeout, and navigation/disposal.
6. Keep download and other valid actions stable and tappable while details are displayed. A refresh must not repeatedly replace the page content, disable unrelated controls, or cause buttons to disappear.
7. If background synchronization is genuinely necessary, use a justified, bounded strategy that does not block the UI. Explain why it is necessary.
8. Preserve correct handling of completed, failed, expired, and downloadable exports.

**Acceptance criteria:**

- Leaving Resume Details open for at least 30 seconds does not trigger unexplained repeated refreshes.
- Opening the page performs the required initial load without duplicate overlapping requests.
- The download action remains visible and usable while the page is idle.
- A legitimate manual refresh works and displays an appropriate loading state without destabilizing the page.

4. Ensure a successful save is acknowledged and the latest server-confirmed profile is used for Preview and Export.
5. For ambiguous save outcomes, use the existing safe recovery mechanism to check the authoritative saved state before retrying. Avoid duplicate writes and lost edits.
6. Handle offline states, timeouts, retries, app navigation, and process restarts without leaving the user permanently blocked.
