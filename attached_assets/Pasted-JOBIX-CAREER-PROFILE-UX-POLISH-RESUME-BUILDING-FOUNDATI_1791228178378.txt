1. STEP 1 — PERSONAL INFORMATION

Step 1 is the first builder screen.

There MUST NOT be a Back button on Step 1.

The user should only have the forward/Continue action.

### Profile photo

Allow the user to optionally select/upload a profile photo from the device.

Requirements:
- optional
- user can select an image from the device
- user can replace/remove it
- do not make it required
- preserve the profile photo with the Career Profile if the current architecture supports it safely
- do not introduce insecure public storage

Use the existing architecture/security rules.

### Additional links

The user must be able to add links beyond the predefined suggested link types.

For example:
- LinkedIn
- GitHub
- Portfolio
- Website

But also:
- Add another link
- custom label
- URL

The UI should remain clean and professional.

### Input field visibility

The current text input fields are too transparent against the background.

Improve the input fields so that:
- text fields are clearly distinguishable from the page background
- borders/surfaces have sufficient contrast
- focused state is obvious
- error state is obvious
- disabled state is obvious
- typography remains consistent with Jobix
- the result remains visually consistent with the supplied screenshots

Do not use generic Material styling if it conflicts with the Jobix visual language.

### CV language indicator

The Resume/CV language selector must make the current selection visually obvious.

The user should immediately understand:
- English selected
or
- Arabic selected

Use a clear selected state, such as:
- highlighted segmented control
- check indicator
- selected chip
- flag/language marker where appropriate

Do not confuse Resume language with App Language.

Changing CV language changes Resume/output direction/configuration only.

It does NOT translate the user's content.

### Country autocomplete

Country selection must support autocomplete.

The country suggestions must use the selected CV language:

If CV language = Arabic:
→ country names should be presented in Arabic.

If CV language = English:
→ country names should be presented in English.

Use a local/reference country dataset.

Do not call an external API for basic country autocomplete.

### Email autofill

The email field should initially be prefilled with the authenticated account email when available.

The user MUST still be able to edit it.

This is convenience only.

Do not treat it as verified just because it came from the auth account.

### Email validation

Do NOT show email format errors while the user is still typing.

Validate:
- on field blur
- or on submit/Continue

The error should appear only after the user leaves the field or attempts to continue.

Do not create an annoying real-time error while typing.

2. STEP 2 — PROFESSIONAL SUMMARY
==================================================

Keep the approved Summary constraints:

- minimum 50 characters when included
- maximum 1,000 characters

Improve the guidance content.

The user should see a small set of expandable questions that help them generate authentic information that can later be refined by Jobix AI.

Use no more than 6 questions.

Use these questions:

1. What is your professional background?
Example:
"Software engineer with 4 years of experience building mobile and web applications."

2. What are your strongest skills or areas of expertise?
Example:
"I specialize in Flutter, backend APIs, and building reliable user-focused products."

3. What type of work or problems are you best at solving?
Example:
"I enjoy turning complex business requirements into simple, scalable software."

4. What are some achievements or results you are proud of?
Example:
"I helped reduce application processing time by 30%."

5. What type of role or work are you looking for next?
Example:
"I am looking for a product-focused software engineering role."

6. What makes you valuable to an employer or team?
Example:
"I combine technical execution with strong communication and cross-functional collaboration."

IMPORTANT:
These are prompts/examples only.

Do not populate the user's Summary automatically with these examples.

Do not invent achievements.

The future AI system can use the user's answers as source material.

Keep the UI visually close to the supplied Summary screenshot.

3. STEP 3 — WORK EXPERIENCE UX
==================================================

The current implementation incorrectly treats every field as if it has the same 200-character limit.

Fix this.

Do NOT impose one generic 200-character limit on every field.

Use appropriate field constraints based on the field's purpose and Architecture/Product Design.

For example:
- Job Title → short field
- Company → short field

- Start Date → date input, not character-limited prose
- End Date → date input, not character-limited prose
- Description → meaningful longer text field

Approved description range:
20–1,500 characters.

Do not display a character counter on fields where a character counter is not useful.

Only show counters where they materially help the user.

The current UI tells users to type:

but the keyboard only provides numeric input, making the "-" impossible to type.

Fix this professionally.

Preferred behavior:
- use a dedicated month/year picker if appropriate
OR
- use a masked input that automatically inserts the "-" after the first four digits.

The user should not have to fight the keyboard.

The resulting stored format can remain:
YYYY-MM

but the input experience must be mobile-friendly.

Validate:
- valid year
- valid month
- start <= end
- Present state where applicable

It should visually communicate:
- Improve with Jobix
- future AI enhancement
- AI-generated version will appear here

DO NOT fake an AI result.

The component must be designed so it can later display:
- Original
- AI Generation
- Keep Mine
- Use This
- Edit Before Accepting

This must be compatible with Architecture V2's AI generation/history model.
