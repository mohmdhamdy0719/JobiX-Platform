## Current source and recent completed work

### Resume Preview, export, and editing

- Local Preview is integrated into the Resume journey. It assembles the saved
  Profile, custom links, section configuration, language, and supported
  presentation settings; unsaved edits and device-only Drafts do not silently
  become authoritative data. Preview must not create export jobs or mutate
  Credits. See `mobile/jobix/docs/profile-entry-drafts.md` for the current
  device-only Draft rules.
- The latest fix distinguishes saved-data identity from serialized HTML bytes
  generated by separately built local and server renderers. The client still
  checks saved versions/configuration and any available server source hash.
  Export still fetches the authoritative server document and retains its
  server-side version/hash checks, normal Credit confirmation, idempotency,
  retry, and uncertain-outcome protections. Do not add a write path that fails
  to advance the corresponding saved version.
- Review now displays localized counts of authoritative, saved, complete
  entries. Incomplete saved entries and local Drafts are not relabelled as
  complete; Volunteer retains its existing “added” treatment and completeness
  rules.
- Education’s empty “Other” degree value previously cleared the selection while
  the user edited its custom title. That state is now retained, while the
  required-title validation remains in force. Standard-degree save/reopen/edit
  is covered in English and Arabic.
- The Personal Information title, Resume-language alignment, Career
  language-dialog contrast/spacing, responsive template card/title, Skills
  keyboard navigation, and Add-button shape were refined. The selector uses the
  selected template ID; constrained content scrolls rather than being clipped.

### Android PDF download

- Android previously treated a document-provider final-size response of zero
  as the actual saved-file size even when the complete PDF had been written.
  The save path now flushes/closes its output and verifies destination bytes by
  read-back when available. If read-back is unavailable, success requires exact
  write/close evidence; a partial/read/close/write failure is not converted to
  success. No duplicate download or export is initiated by this verification.
- A pure-JVM test covers 14 verification cases. Kotlin/Java compilation was
  included in the Development APK build.
- **Owner-confirmed historical device result:** an existing completed PDF
  downloaded and opened successfully on the owner’s Android phone after the
  earlier download fix. That result applies to the APK tested at that time, not
  automatically to the latest APK recorded below.
