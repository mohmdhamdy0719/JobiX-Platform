### 1. Resolve the completed-entry / draft-edit behavior

Review this exact scenario for all applicable career sections:

1. A user has an existing Complete entry saved on Supabase.
2. The user edits it and removes or changes a required field, making it incomplete.
3. The user selects **Save as draft**.
4. The user later reopens the draft, completes it, or discards it.

Determine whether the current implementation converts the original Complete row into a Draft and consequently removes it from Resume Preview/PDF.

Recommend and implement the safest behavior consistent with JobiX's existing architecture:

- Supabase remains the authoritative source.
- Do not silently remove an existing Complete entry from the Resume just because an edit is incomplete.
- Prefer preserving the existing Complete entry while storing the incomplete edit as a separate Draft, if this can be implemented safely without excessive scope.
- If separate drafts are not compatible with the current architecture, explain the trade-offs and propose the smallest safe alternative before implementing a destructive behavior.
- A genuinely new incomplete entry should still be savable as a persistent Draft.
- Completing a Draft should use a stable record ID and become visible only after the authoritative save succeeds.
- Discarding a Draft must never delete a Complete entry.
- Preserve idempotency, version-conflict handling, RLS, uncertain-outcome reconciliation, and server-side exclusion of Drafts from Resume Preview/PDF.
